# 配置与标定状态

只编辑 `configs/standard.yaml`。启动器读取它并生成 `logs/xuc-bringup/field_autoaim.runtime.yaml`，仅覆盖已保存的敌方颜色。不要修改这个生成文件；下次启动会重建。

颜色保存在 `~/.config/sp-vision/field_autoaim_enemy_color`。标定工具使用 `configs/calibration.yaml`，其历史外参与正式运行配置并不相同；二者用途不同，不能互相覆盖。

用户最新安装测量：机器人中心为原点，X前、Y左、Z上，右手系；光心(15,0,50) cm，机身(10,0,50) cm，炮口(10,0,45) cm。测量记录尚未应用。代码中的相机、云台、IMU坐标原点和轴定义仍需核对，再完成标定。

标定源文件在 `calibration/`；原始采集资料集中保留于小电脑 `data/`。旧实验配置和旧报告已清除，工作区不保留候选参数副本。

## 暂时丢失时的请求开关

`xuc_fire_inhibit_temp_lost: true`（未配置时也默认为 true）禁止暂失请求并清除资格。
当前设为 `false`，只允许暂失前已满四帧、尚未发送的同模型、同预测几何、同候选面
在 `xuc_fire_temp_lost_max_age_ms: 50` 内延续。年龄从最后一次可信关联观测的图像时间
起算，包含处理、等待和发送前耗时；预测帧不会刷新观测时间，候选帧数在暂失期间冻结。
不足四帧、超时、完全丢失、换面、换模型、重建、预测失效或模型不可信均撤销资格。

暂失时使用当前有效预测检查偏航，以当前反馈姿态投影模型检查可见性；保留已有
平滑 pitch 指令，并要求其与反馈的偏差不超过原 1.1°。实测新鲜度标记始终保留原意。
候选与发送末端共用门控，发送前重新检查年龄、模型及反馈；诊断不能生成额外请求，
保持脉冲不得在暂失期间延续已发送请求。已发请求的反馈配对继续保留。

`[FIREGATE]` 在门控、来源、预测失败阶段或模型/候选面变化时输出，持续受阻每 250 ms
汇总；`closed` 列出所有关闭的门，同时记录真实预测偏航误差、实测/预测来源、观测年龄、
模型代际及候选计数。预测失败阶段为 `no_target`、`initial_selection`、
`iterative_selection`、`trajectory` 或 `non_finite`。`AIMPRED` 增加来源和观测年龄。

修改配置后需重新启动程序；新增开关的源码需要先重新编译 `standard`。

## 请求节奏

2026-10-25 已移除 700 ms 固定节拍试验，恢复按当前资格与原有最小间隔逐帧判断。
固定节点会与有效窗口错开，停用原因和日志证据见 [工作日志](status.md)。
`xuc_fire_cadence_fallback_ms` 大于零时要求距上次请求达到该间隔，
为零时按原有反馈可用性判断；满足间隔后仍须重新通过候选帧数、当前观测和择时门控。
这不是按固定节点发令，也不积压失效期间的请求。本地与现场最小间隔均为 1100 ms。
`xuc_gyro_fire_selection_max_wait_ms: 0` 取消额外择时，当前条件满足且满四帧即进入
发送判定；原偏航门限、pitch 平滑、重建次数及预测延迟不变。

## 稳定旋转的转速预测对照

`xuc_rotation_prediction_mode` 取 `off`、`shadow` 或 `active`，缺省 `off`；其他值启动即报错。
当前现场为 `shadow`：新增估计器只在原发送完成后计算并记录，**不改变指令、候选、请求计数
与重建状态**，因此默认开火行为等同于 `off`。只有评审过影子数据后才可改 `active`。

仅当整车四板、主 EKF 状态有限且旋转模式为高速相位时喂入样本。样本只来自 `tracking`、
已收敛、yaw 可信、且指向同一关联检测的**图像时刻**观测；预测副本、暂失帧和几何不一致
的观测都不写入。换代际、完整丢失、重建、重复或倒退时间戳，以及可信样本间隔超过
100 ms 时清空历史。

估计采用最近 2 s 内、至少 30 点且跨度 ≥1.5 s 的主相位线性拟合，要求拟合 RMS ≤5°、
前后半窗各 ≥6 点且斜率差 ≤0.5 rad/s、方向与当前主模型一致、|ω| 不超过
`yaw_eskf_max_trusted_abs_rate_rad_s`（当前 8.0 rad/s），样本年龄 ≤50 ms。
任一条件不满足即回退原预测，因此显著变速或反转不会被新速率覆盖。

启用后只替换**预测副本**的角速度：以当前主 EKF 相位为起点外推，延迟预测与全部弹道
迭代共用同一速率；车体平移、几何和在线滤波状态保持原逻辑。预测是否仍有效在候选与
发送末端重新检查样本代际和 50 ms 年龄；`active` 下转速来源切换会重新累计候选四帧。

`[AIMROT]` 每 250 ms 及每次请求记录模式、回退原因、样本数、跨度、拟合 RMS 与速率、
计算耗时，以及新旧两条预测的面、时间、角度和有效性。`AIMOBS` 在启用时附带同一诊断
和每次观测的关联结果。影子对照与 `off` 的命令等价性由 `rotation_prediction_test`
断言；该测试同时覆盖固定计算时刻、同一速率快照、平移不变及候选/重建计数一致。

## 按请求次数重新建模

`xuc_model_rebuild_after_requests: 15` 在 XUC 路径启用按次数重建；`0` 或未配置时关闭。
当前模型累计 15 次成功匹配串口写调用的独立开火请求后，在下一帧处理前完整重建。
计数依据 `SHOTTX.tx_call_matches=1` 的请求编号，不是实际出膛数；未发出的请求、
保持脉冲的续帧和重复编号不计数。`temp_lost → tracking` 沿用计数；真正新建目标
（完全丢失后重新捕获或切换目标）则从零计数。

重建清空整车 EKF、YawESKF、单板运动滤波、选板锁、相位调度与相位历史、
模式选择、距离滤波及开火候选。新模型需重新达到 `tracking`、整车收敛和 yaw 可信，
再通过当前观测及原有开火门控才可请求；诊断持续请求及脉冲保持也受此限制。
云台指令平滑、上次可信中心的短时姿态保持、已发送请求的拨弹反馈配对继续保留。
上次请求的时刻继续保留；恢复后重新积累当前资格，并检查原有最小间隔，不积压补发。

`[MODELREBUILD] request` 记录当前模型计数，`scheduled=true` 表示下一帧重建；
`begin`、`acquired`、`ready` 分别记录重建开始、重新捕获与新模型可信，
`ready.elapsed_ms` 给出本轮建立可信模型所需时间。`AIMPRED`、`AIMOBS` 增加
`model_generation`，用于区分没有空目标间隔的模型重建；该编号不代表物理目标或装甲板身份。
配置在启动时读取，需要重新编译并启动程序。命中率变化和实际建立耗时仍需试射日志验证。

## XUC IMU 回传单位

当前连接的下位机由用户于 2026-10-09 确认以度回传 yaw/pitch。正式配置使用
`xuc_imu_angle_unit: deg`；驱动在接收层转换为弧度，再应用符号和弧度偏移。
所有姿态接口（包括 `raw_imu_yaw()`）输出弧度，手眼采集可直接用于 `Eigen::AngleAxisd`。
发送目标角的格式和单位保持原协议约定的弧度；回传单位的确认不代表发送单位已实车验证。

`xuc_imu_angle_unit` 只接受 `deg` 或 `rad`，未配置时默认 `rad`，兼容原弧度固件。
更换下位机固件时须同步核对该项。可只接收检查：

```bash
./build/xuc_board_probe /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0 460800 5 --imu-unit=deg
```

探测程序同时输出弧度和度，默认不发送控制或射击指令。

## 手眼采集与计算

2026-10-10 用户现场确认 yaw、pitch 读数准确。正式运行与标定配置均使用
`xuc_imu_yaw_sign: -1`，不再额外乘旧的 1.06298816；对应的发送侧倒数补偿也移除，
`xuc_yaw_sign: 1`。pitch 系数保持现有方向，发送角度仍为弧度。

XUC 接收线程保留两秒的成对 yaw/pitch 历史，采集按图像时间插值，跨 ±180° 使用短弧。
没有前后姿态、包间隔超过 30 ms、未连续停稳 500 ms（两轴变化范围各 ≤0.05°）时拒绝保存。
图像保存时超过 100 ms 也拒绝保存；相机队列满时丢弃旧帧。
对应设置为 `capture_pose_stable_window_ms`、`capture_pose_stable_range_deg`、
`capture_max_frame_age_ms`。采集目录必须没有已有图片/姿态，避免覆盖；保存时间信息到该目录的
`samples.csv`。这些时间戳来自主机接收时刻，**仍不是相机曝光与 IMU 硬件同步时间戳**。

`calibrate_handeye` 默认先求 Tsai 初值，再联合优化一组相机外参及固定棋盘位姿，
使所有角点的重投影误差最小。内参和实测 IMU 姿态保持固定。使用 `--no-refine` 可回放原方法，
`--self-test` 验证合成数据。计算仅输出候选结果，须通过原有验证门槛后才能采用。
原始数据应覆盖 yaw、pitch 多个方向，棋盘和云台底座固定，每次等画面显示 READY TO SAVE 再保存。

## 相机采集窗口

海康采集使用 2048×1200，在 3072×2048 传感器上设置 `camera_offset_x: 512`、
`camera_offset_y: 424`，使窗口位于传感器中部。采集上限为 60fps，曝光为 3ms；
仅横向扩大视野，高度保持 1200。处理频率和画面亮度须以实际运行结果验证。驱动先清零偏移，再设置尺寸和最终偏移；
设置失败时不启动采集，实际尺寸与偏移记录于 `[HikRobot][READBACK]`。

这只是裁剪平移，内参主点从 (1465.505908, 1053.887837) 改为
(953.505908, 629.887837)，焦距、畸变和相机外参保持原值。正式与标定配置必须一致。
历史图像的裁剪原点仍为 (0,0)，重新分析这些图像时必须使用其原主点；不要直接套用新内参。

USB 相机使用 4 个异步传输节点，避免扩大画面后默认 8 个节点触及 Linux 默认
16MiB 的 usbfs 缓冲上限。若仍报 `MV_CC_StartGrabbing: 0x80000006`，
继续检查 SDK 资源分配与 USB 缓冲；帧率设置成功不代表取流已启动，须以首帧日志验证。

## 当前协议的 yaw 平滑条件

当前反馈的 `robot_id` 是编号，不再解释为旧固件的解锁位。yaw 最终限速在允许控制、
反馈新鲜且反馈模式为自动模式时生效；停控或模式退出时仍按实际反馈角重置限速状态。
保留 30°/s 上限和既有滤波，未开启额外 PI 控制。进入限速分支时打印
`[XUC][YAW] final slew limiter active`。该限制约束指令变化速度，不代表电机实际运动速度。

## Pitch 可信观测与平滑

`xuc_direct_pitch_guard` 只使用当前跟踪关联成功的检测，并检查位置有限、目标位于前方、
云台系与世界系坐标满足当前旋转变换；不从 yaw 回退检测读取可能尚未求解的位置。
`temp_lost` 或位置无效时保持上一次可信 pitch 目标，保持窗口由
`xuc_direct_pitch_hold_ms` 指定，超时停止视觉跟随；若常驻姿态保持开启，仍可按既有逻辑锁定当前姿态。
保持的观测不作为新鲜 pitch 实测参与开火资格。

`xuc_direct_pitch_filter_tau_ms: 100.0` 对可信目标做一阶滤波，
`xuc_direct_pitch_max_rate_dps: 10.0` 限制指令每秒变化量；约 60 FPS 时每帧不超过 0.167°。
首次控制和长丢失恢复时从当前 IMU pitch 起步，再逐帧接近目标，避免一次跳到新目标。
这些限制约束指令，电机实际波动和命中效果仍需现场日志确认。配置在启动时读取，源码更新需重新编译。

## 逐发预测回看日志

启动时的 `[AIMAUDIT] schema=1` 表示已启用本组诊断。新增日志在发送调用之后写入，
只记录观测，不改变预测、控制或开火判决；不需要新增配置项。

- `[SHOTTX]` 保留原字段，追加 `image_ns`、`issue_ns`、`tx_call_ns`。
  只有 `tx_call_matches=1` 的串口写调用才与该请求匹配；写调用不等于出膛。
- `[AIMPRED]` 后为 JSON，以 `id` 对应 `SHOT/SHOTTX`。记录实际 Aimer 的几何来源
  `geometry`、所选 `face`、原始主 EKF 状态 `raw_state`、实际使用的输入状态 `model_state`、
  最终预测板位置和朝向 `aim_xyza`、迭代次数、有效性和弹道迭代收敛结果。
  `base_prediction_ns` 是加入执行延迟后的基准时刻，`prediction_ns` 是最终板位置对应的时刻；
  `delay_ms`、`flight_used_ms`、`flight_solved_ms` 分别记录实际采用的延迟、最后一次外推使用的
  飞行时间和最终弹道解的飞行时间，避免用独立的相位窗口诊断代替真正的 Aimer 预测。
- `[AIMOBS]` 后为 JSON，在发送成功匹配后逐帧记录至预测到靶时刻之后 100 ms，
  连续请求的窗口合并。记录当帧主 EKF、有效相位状态、云台反馈及当前关联检测的求解位置、朝向。
  `pose_fresh=false` 时测量位置为空数组、测量朝向为 null，不能把保持或丢失中的模型当成新观测。

所有 `*_ns` 都是本进程使用的单调时钟纳秒，不是 Unix 时间；按 `image_ns` 对齐图像，
按 `prediction_ns` 查找后续观测，不按日志行显示时间对齐。`tx_to_prediction_ms` 是发送到
预测到靶的剩余时间，仅在预测有效且发送匹配时存在。非有限浮点量输出为 JSON null。

状态数组顺序为 `[cx,vx,cy,vy,cz,vz,phase,omega,radius,radius_delta,height_delta]`，
位置用米、速度用米/秒、角度用弧度、角速度用弧度/秒；`aim_xyza` 为 `[x,y,z,face_yaw]`。
`frame` 是本轮程序处理的帧序号；`segment` 仅在目标由空变为非空时递增，辅助排除失踪后重建的片段。
模型 `face`、`segment` 及检测类别 `target_name` 都不能直接解释成靶车上人为标注的物理板编号。
后续观测可检验预测自一致性，实际出膛时刻和命中仍需外部测量或同步视频确认。

## 图像颜色约定与排查（2026-10-12）

相机接口、传统颜色判定、灰度转换、OpenCV 显示、图片和录像保存统一使用 BGR。
海康和大恒的 Bayer 解码按实际排列映射；MindVision 设置 BGR8，USB VideoCapture 使用 BGR。
不要因颜色看起来不对而在显示或保存入口再次交换红蓝。

当前 `assets/yolo26.xml` 元数据为 `reverse_input_channels=YES`，输入直接进入量化和卷积，
没有内置通道翻转。主机张量声明 BGR，OpenVINO 推理前显式转换一次到 RGB；颜色判定和显示
仍使用原始 BGR。`yolo26_swap_rb` 保持 false，不能用于补偿显示问题。

YOLOv5/v8 显示和保存已移除旧的重复转换。YOLOv5/v8/11 的主机张量标注改为真实的 BGR，
没有据此改变其模型输入数据顺序；小电脑没有这些模型文件，模型所需通道仍须按对应导出文件核验。
YOLO11 TensorRT 的推理入口 BGR→RGB、能量机关备用函数的可选 BGR→RGB 属于模型边界，保留。
YOLOv8 TensorRT CUDA 路径保持 BGR，当前环境未验证其 engine 输入约定。

标定 capture、内参、手眼验证、分类器、录像和普通相机测试已扫描，未发现额外重复换色。
当前显示反色来自远程 standard 的旧 RGB→BGR 转换，本轮已删除并与本地显示逻辑对齐。
Bayer 映射通过合成红/绿/蓝色块验证；备用相机和 TensorRT 尚无现场运行验证。
